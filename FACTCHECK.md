# Fact-check of the milo-arc session

The transcript stays as it was: its mistakes are part of the record. This file checks the factual claims Claude made in it against primary sources, seven months later. Evan's own statements were not checked, and the analogies in turn 2 ("X is the Milo") are framing, not claims. Only the factual assertions inside them were checked.

**Checked 17 November 2026.** 33 claims: 2 wrong, 11 partly right, 2 with no source found, 18 confirmed. Each was judged as of 23 April 2026, when it was said. Line numbers refer to [`transcript.md`](./transcript.md).

The transcript is lossy. Bullet lists in Claude's turns were stripped when it was exported (for example lines 33–37, 41–49, 168–170), so line 238's "I called it 'Introduce an auxiliary element'" refers to text that is no longer on the page. Only what is on the page was checked.

Every row in the tables cites a page and a short verbatim quote. [`check_quotes.py`](./check_quotes.py) fetches each page and confirms the quote is still on it (`python3 check_quotes.py FACTCHECK.md`; needs `curl` and `pdftotext`). That proves the quote exists, not that the conclusion drawn from it is right. Unlike the copy in road-traffic, this one also fails if a table row does not parse, so a malformed row cannot drop out of the count silently.

This check was done by AI agents too. Three Claude subagents did the first pass, one per topic, and checked each of their quotes with the same code the checker uses. The verdicts marked wrong were then re-read against the primary source by the agent that assembled this file. GLM-5.3 (a different model family) reviewed the verdicts as a skeptic and found no blockers. Changes that came from it: the K6 quote now includes "using Cartesian coordinates", so it no longer reads as contradicting the claim; K3 no longer says no source uses the terms; K2 no longer implies anything about proportions; and T4b is described as closely following its source rather than as a paraphrase. Treat all of this as a stronger second opinion, not as ground truth.

## What changes the story

In turn 4 (lines 232–280) Claude fact-checked itself with web search, and then used the result to build the five-layer silo diagnosis. That self-check is the part of the session most worth re-checking, because the README's lessons rest on it.

- **Layer 4's evidence says the opposite of "never"** (T3, wrong). Line 271 says people given two structurally identical problems "never noticed the connection, even back-to-back", and that the skill is "literally invisible" to those without it. Gick & Holyoak's subjects read a story, not a second problem, and about 30% then solved the radiation problem unprompted (75% with a hint, under 10% with no story). The authors' own reading is that "a third or less" noticed. The same paper's main finding is that giving people **two** analogs raised spontaneous transfer from 21% to 45%. That supports the session's prescription (build the schema deliberately) and weakens its diagnosis (the skill cannot be seen without being taught).
- **Layers 1, 3 and 5 each rest on one quoted snippet** (T4). The Layer 1 quote ("not even a place on the library bookshelves") could not be traced to any page. The Layer 3 quote closely follows a TRIZ consultant's 2008 TRIZ Journal essay, which calls it "a common finding" and gives no data. The Layer 5 quote traces, through search summaries only, to a single-school TRIZ-teaching pilot behind a paywall. Every source that was found comes from the TRIZ-teaching community. The diagnosis may be right, but the session argued it more than it evidenced it, and the README presents it as found ("The five-layer silo is load-bearing").
- **The self-check missed one error and "corrected" another to an equally weak figure** (T1, T2). Line 173 gives the Russian for TRIZ as "Алгоритм решения изобретательских задач". That is ARIZ, the algorithm inside TRIZ. TRIZ is "Теория…" (theory). The self-check did not catch it. It did change "400,000 patents" to "200,000" and called the first figure inflated, but both numbers circulate in secondary sources, along with 40,000 (Russian Wikipedia) and 1.5 million (the later community total). Its description of English Wikipedia ("hundreds of thousands", no exact figure) was accurate.

Two smaller points about the opening and the tooling advice:

- The chemistry answer named the failure mode "incomplete wetting followed by agglomeration" (K1). In dairy science, agglomeration is the manufacturing fix that improves wettability, and the failure is called lumping. Milo's label lists milk powder first, which "mostly sugar, cocoa, and malt extract" leaves out (K2).
- For injecting the protocol "at session start", the advice named a PreToolUse hook (M4). Claude Code already had a SessionStart hook for exactly that, and PreToolUse fires only when a tool is about to run. CLAUDE.md was also described as a "system-level instruction" that "fires unconditionally" (M1). The docs say it is delivered as a user message and treated as context, not enforced.

The README's list of names for the pattern (Polya's auxiliary element, TRIZ Principle 24 "Intermediary", Gentner's structural alignment, Gick & Holyoak's schema induction) all check out, as does Principle 10 for the dry-mixing step.

- **T4a (line 257), Layer 1:** "Problem solving skills are not taught in schools, and there is not even a place on the library bookshelves devoted to the problem solving process." Four search phrasings found no page with this wording.
